# D-DBA-36: Mode A checks return script lines; only `advise` writes them to a file, and nothing in the pack runs it
**Status:** Accepted
**Date:** 2026-11-14
**Issue:** DBA-36
**Confluence:** none (design in epic DBA-23)

**Decision:** A mode `A` (advisory) check returns one row per script line: an integer `LINE_NO` (script order, strictly increasing, gaps allowed) and a `SCRIPT_LINE` of at most 400 characters, besides `SEVERITY` and any facts columns. Lint code L018 requires a mode A check to alias both `AS line_no` and `AS script_line`, and refuses `AS script_line` in a mode R check. `tools.checks.run.validate_script_result(check, result)` checks the two columns at run time, next to an unchanged `validate_result`. `python -m tools advise <id> --connection NAME` is the only code that turns such a result into a file: it loads the check through `tools.checks.target` (overlay, lint gate, `--param`), refuses any mode but `A` (exit 2), runs the check once on the advisory tier's home, validates the result (exit 1, nothing written), then writes `<pack_home>/scripts/<id>-<YYYYmmdd-HHMMSS>.sql` (or under `--out-dir`), mode 0600, with a comment header and the `SCRIPT_LINE` values sorted by `LINE_NO` as numbers. It never runs the script, sends nothing more to SQLcl after the check, and starts no process.

**Why:** SQLcl runs at restrict level 4 (D-DBA-15-sqlcl-explicit-restrict-level-4), which refuses `spool` and `host`, so the database session cannot write a file; a local tool must. Keeping the script in the check's result keeps the text testable on the container and identical to what the user receives. Running the script stays with the user, so database privileges remain the guard: the advisory tier can read advisor output but cannot change data or structure (D-DBA-26-advisory-tier-grants).

**Rejected:** `spool` or `host` from the SQLcl session: refused at `-R 4`, and lowering the level would let the session run operating system commands. The model writing the file from the chat transcript: untestable, and the text could drift from the check's output (a dropped line, a reordered `ENABLE ROW MOVEMENT`). Sorting lines in the tool by anything but `LINE_NO`: the order is part of the script (row movement must be enabled before a shrink), and only the check knows it.

**Impact:** A new mode A check aliases `line_no` and `script_line`, passes L018, and is run through `advise`, never through the SQL-running tool; skills report the file path and never execute or forward the lines. The per-check harness runs mode A checks as the `adv` session and requires `validate_result` and `validate_script_result` to be empty. `tools/commands/advise.py` starts no process and calls SQLcl only for the one check (`tests/unit/test_advise_command.py` enforces the first). A script line that would exceed 400 characters is not cut: the check writes a `-- ` comment line instead (as `reclaimable_space` does). The next free lint code is L019.
