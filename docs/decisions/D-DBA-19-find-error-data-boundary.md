# D-DBA-19: find_error ends a footerless CSV block at a blank or `Error report -` line
**Status:** Accepted
**Date:** 2026-11-12
**Issue:** DBA-19
**Confluence:** none (design in epic DBA-1)

**Decision:** With no row-count footer, `find_error` treats the text from the CSV header (first line opening with `"`) to the first blank line or `Error report -` line outside a quoted field as data and does not search it. Quote state is tracked by counting `"` per line (odd count toggles it). With a footer the block ends at the footer, as before. A quote-led line between `Error starting at line` and `Error report -` is echoed statement text, not a CSV header (DBA-20).

**Why:** SQLcl prints no footer under 6 rows, so codes stored in short results were reported as errors. Observed on the test container (Oracle 23.26.3, SQLcl 26.3): SQLcl writes a blank line after the last record; a NULL string prints as `""`; a NULL number prints as an empty field, so in a one-column numeric result it is an empty record and ends the block early, but the rows after it are numbers and hold no code; a statement that fails in its first fetch returns an error report with no rows (a failure in a later fetch returns the rows fetched so far and no error: D-DBA-20-accept-truncated-result-on-fetch-error). An echoed multi-line statement can hold a line opening with `"` (`select\n"DUMMY"\nfrom no_such_table`), which `_layout` takes for a header; without the `Error report -` stop, the block hid the real ORA-00942 after it.

**Rejected:** `csv.reader` over the block to find its end: raises `csv.Error` on a field over `csv.field_size_limit()` (131072 characters by default, reachable with a CLOB), and `find_error` must not throw on odd text. Searching the error report first and skipping CSV handling when one is present: a quoted multi-line field holding a line `Error report -` would then be searched as error text, which the quote-aware stop avoids. Ending the block where a record's field count differs from the header's: cannot tell a one-column result from a bare error line. Moving the boundary into `_layout`: would change `parse_csv` for footerless text, which DBA-19 keeps out of scope.

**Impact:** Code that changes `_layout`'s header rule or SQLcl's output format must keep `tests/unit/test_sqlcl_text.py` (`ECHOED_QUOTED_LINE`, `ECHOED_ODD_QUOTES` and the no-footer cases) passing. `parse_csv` still reads a footerless block to the end of the text; in a one-column result it keeps an empty line as a NULL row (DBA-20), so it cannot share `_block_end`. Known miss of the header rule: a PL/SQL compile error with no preamble (`bug.md`, found in DBA-20 /review).
